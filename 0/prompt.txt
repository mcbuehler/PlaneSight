  Research report: Entire and Herdr facts for the Agentic AI Hack Zürich pitch. All facts come from primary sources: the hackathon page, docs.entire.io, the herdrdev/herdr repo docs, and the brief PDF in the repo. Unconfirmed items are marked.
  
  ## 1. Entire
  
  **What it is.** The hackathon page says: "Entire is the git forge for AI-native teams. The Entire CLI captures every AI coding agent session, so the reasoning behind the code stays with the git repo, right next to your code." Continuous Memory turns those sessions into knowledge that agents can use. It also offers Git hosting and mirrors of GitHub repos.
  
  **Concepts**
  - **Checkpoint:** a save point that links a Git commit to the agent sessions and decisions behind it. The link is made with the commit trailers `Entire-Checkpoint` and `Entire-Attribution`. `Entire-Attribution` records how many lines came from the agent and how many from a human.
  - **Trail:** from the glossary: "Entire's unit of work, covering one branch and one pull request from one intent to shipped code." A Trail groups the intent, the checkpoints, and a rolled-up summary and report. Teams review the Trail instead of the raw diff.
    - Each Trail is backed by a GitHub PR for CI.
    - Runners are AI agents that run in cloud sandboxes and are defined in `.entire/runners/`. They evaluate each push and raise findings, with scores for risk, drift, confidence and security. Open findings block the merge.
    - Trails is behind a feature flag. You request access with a form.
    - Commands: `entire runner setup -y` and `entire trail create`.
  - **Continuous Memory** is Graph plus Brain.
    - **entire-graph** is a plugin that gives agents a map of the codebase: implementations, relationships and change impact. Entire claims it saves up to 71% of token spend. Commands: `entire plugin install graph`, `entire graph init-agents --repo .` and `entire graph stats --repo .`. The stats command reads Claude Code transcripts to estimate the tokens saved.
    - **entire-brain** is a memory layer that lives in the repo: sessions, checkpoints, facts, docs and code structure. It carries context across agents, for example from Claude Code to Codex. Commands: `entire brain setup`, `entire brain status` and `entire brain init-agents`. A background watcher extracts facts from sessions, and that extraction uses an agent and costs tokens.
  
  **Other CLI commands:** `entire enable`, `entire status`, `entire session list|current|info|tokens|stop|attach|adopt|resume`, `entire checkpoint list|explain`, `entire search` (semantic, or `--code` for literal text), `entire why`, `entire blame`, `entire recap`, `entire dispatch`, `entire review`, `entire investigate`, `entire tokens`, `entire doctor` and `entire api`.
  
  **What it captures.** For Claude Code, hooks in `.claude/settings.json` capture session boundaries, prompts, completed turns and task events. Entire then reads the full conversation, file changes, tool calls and token usage from the JSONL transcripts, including subagent sessions. A session holds prompts, responses, code changes, checkpoints, token usage, metadata and line attribution. `session info` shows the agent, model, status, worktree, timing, tokens, checkpoint links and files touched. Built-in integrations are Claude Code, Codex, Cursor, Copilot CLI, Antigravity, Factory, OpenCode and Pi. Other agents can be added through the Agent Integration Protocol.
  
  **Can a third-party tool read it? Yes, in several ways.**
  - **Files in the repo, readable with plain Git:**
    - The default backend stores one ref per checkpoint at `refs/entire/checkpoints/<shard>/<ULID>`. List them with `git for-each-ref refs/entire/checkpoints/`.
    - Repos enabled before CLI 0.10.0 use the `entire/checkpoints/v1` branch instead.
    - During an active session, checkpoints sit on local shadow branches named `entire/<commit>-<worktree>`, which are never pushed.
    - Settings live in `.entire/settings.json`.
  - **CLI JSON:** `entire session list --json`, `entire session info ID --json`, `entire session current --json` and `entire status --json` all return JSON. `--transcript` streams the raw transcript.
  - **MCP:**
    - `entire mcp` is a read-only stdio server with only two tools: `agent_help` and `entire_status`.
    - `entire brain mcp` is Brain's MCP server. I did not check its tools list.
    - The docs themselves are an MCP server at `https://docs.entire.io/mcp`.
  - **HTTP API:** `entire api PATH` makes authenticated requests. OpenAPI specs are listed in docs.entire.io/llms.txt, but the docs warn these are "internal endpoints [that] may change without notice."
  
  **For our idea:** Entire's session states are active, stale and stopped (plus resumed, adopted, attached and imported). It does not report whether an agent is blocked or waiting for input. Herdr is the source for that.
  
  **The ten suggested ideas (verbatim titles and descriptions)**
  1. **Hand off work between agents without losing context.** "Start a feature in Claude Code and finish it in Codex. Use Brain to carry the decisions and rejected approaches across, and Graph to point both agents at the same code. Show the second agent picking up the work without being re-briefed."
  2. **Prove what Continuous Memory saves.** "Run the same set of tasks with and without Graph and Brain. Compare tokens, time and correctness, using entire graph stats for the token savings, and publish the results with links to the sessions behind each run."
  3. **A debugger for agent mistakes.** "Start with a failing test or bug, inspect the affected code with Graph, and trace relevant checkpoints to find where an incorrect assumption entered the implementation. Show the evidence behind the diagnosis."
  4. **A reviewer that checks intent.** "Compare the original request with the committed change. Flag missed requirements, unexpected behavior, and claims that lack test evidence, with links to the relevant transcript and code."
  5. **A "before you build" assistant.** "Search previous sessions for similar attempts and rejected approaches, then use Graph to locate reusable code. Produce a short briefing before the agent starts editing."
  6. **An architecture drift detector.** "Compare Graph snapshots across commits to spot new dependencies or unexpected coupling. Attach checkpoint context explaining why each change was introduced."
  7. **An onboarding guide you can question.** "Let a new teammate ask, "How does authentication work, and why was it designed this way?" Combine current code relationships with historical decisions and source links."
  8. **A regression test scout.** "Use a checkpoint's changes and Graph relationships to suggest behaviors that need tests. Consult session context for edge cases the agent discussed but may not have covered."
  9. **A checkpoint-to-demo generator.** "Turn a checkpoint into a concise walkthrough: the problem, key decisions, implementation, and recorded validation. Generate a shareable page with links back to the evidence."
  10. **An integration for your favorite unsupported agent.** "Build an adapter that captures its sessions and connects them to commits. Ship it with lifecycle tests and a working checkpoint demo."
  - **Other:** "Feel free to be creative and impress!"

  ## 2. Herdr
  
  The repo `ogulcancelik/herdr` now redirects to `herdrdev/herdr`. Herdr marks every pane as working, blocked or idle. It talks over newline-delimited JSON on a Unix socket at `~/.config/herdr/herdr.sock`, which can be overridden with `HERDR_SOCKET_PATH` or `HERDR_SESSION`. `herdr api schema` prints the JSON Schema. The methods below appear in both the released 0.9.3 docs and the next-version docs.
  
  | Need | Supported? | CLI | Socket method |
  |---|---|---|---|
  | (a) List agents and panes with their state | Yes | `herdr agent list`, `herdr agent get <target>`, `herdr pane list`, `herdr api snapshot` | `agent.list`, `agent.get`, `pane.list`, `pane.get`, `session.snapshot` |
  | (b) Read a pane's recent output | Yes | `herdr pane read <id> --source visible\|recent\|recent-unwrapped\|detection --lines N [--ansi]`, `herdr agent read <target> ...` | `pane.read`, `agent.read` |
  | (c) Send keys or text to a pane | Yes | `herdr pane send-text <id> <text>`, `herdr pane send-keys <id> enter ...`, `herdr pane run <id> <cmd>`, `herdr agent send-keys`, `herdr agent prompt <target> <text> [--wait --until STATUS]` | `pane.send_text`, `pane.send_keys`, `pane.send_input`, `agent.send_keys`, `agent.prompt` |
  | (d) Subscribe to state-change events | Yes | `herdr agent wait <target> --until blocked\|done` (one-shot) | `events.subscribe`, `events.wait` |
  
  Details:
  - **(a) States:** the status values are `idle`, `working`, `blocked`, `done` and `unknown`.
    - `done` means idle but not yet seen. Focusing the pane marks it seen.
    - `blocked` means Herdr recognised an approval or question UI.
    - `pane_info` includes `agent_status`. `agent.explain` shows why Herdr classified a pane the way it did.
  - **(c) Prompt caveat:** `agent.prompt` refuses to send input to a `blocked` agent and returns `agent_blocked`. To answer an approval prompt, use `send-keys` or `send-text` instead.
  - **(d) Events:**
    - Example subscription: `{"method":"events.subscribe","params":{"subscriptions":[{"type":"pane.agent_status_changed","pane_id":"w1:p1","agent_status":"blocked"}]}}`
    - Pane events: `pane.created`, `pane.updated`, `pane.closed`, `pane.focused`, `pane.exited`, `pane.agent_detected`, `pane.output_matched`, `pane.agent_status_changed` and `pane.scroll_changed`. There are also workspace, tab, layout and worktree events.
    - Event history is not durable. If a subscriber falls behind, it gets `events_lost` and must resubscribe, then re-read `session.snapshot`.
    - **Unconfirmed:** whether a subscription can cover all panes without listing each `pane_id`.
    - **Unconfirmed:** a CLI command for streaming subscriptions. The CLI reference shows only `agent wait` and `pane wait-output`.
  - **Extras useful to us:**
    - `pane.report_metadata` sets custom state labels and tokens on a pane.
    - `notification.show` shows a toast.
    - `agent.view.set` filters the agent list, for example to blocked or done.
    - `agent.focus` jumps to an agent.
    - There is a plugin API (`plugin.pane.open`) for custom panes inside Herdr.
